The big idea

How a Rails page is built

Every page goes through the same four pieces. Rails finds each one by naming convention.

01 · ROUTE

Address book

config/routes.rb

Which code handles this URL?

→
02 · CONTROLLER

Manager

home_controller.rb

Gets the data ready.

→
03 · VIEW

Picture

home/index.html.erb

HTML for this page's content.

→
04 · LAYOUT

Frame

layouts/application.html.erb

Sidebar + <%= yield %> hole.

The layout is the picture frame, the view is the picture. Every page shares the same frame: that's why every page has the sidebar.
Our homepage will be: root "home#index" → HomeController#index → home/index.html.erb → inside the layout.

Tool · /rails/info/routes

Where do helper names come from?

Open /rails/info/routes while the app runs (development only). Type in the search box to filter.
HelperPathMeaning
teachers_path/teachersAll teachers (no id)
new_teacher_path/teachers/newThe "add" form
teacher_path(t)/teachers/:idOne teacher (needs id)
edit_teacher_path(t)/teachers/:id/editEdit one teacher
Plural = list, singular = one record. teacher_path without an id fails with missing required keys: [:id].
  • One line, resources :teachers, created all of these.

Step 5.3 · Behind the scenes

How did 40 get there?

CONTROLLER

@student_count = Student.count

Runs first. The @ makes it visible to the view.

→
DATABASE

SELECT COUNT(*)

The aggregate you already know. Rails writes it for you.

→
VIEW

<%= @student_count %>

The = means "print the result into the HTML".

You writeWhat happens
@student_countInstance variable: handed to the view ✓
student_countLocal: dies with the method → undefined local variable
ERB tagMeaning
<%= … %>Run Ruby and print the result
<% … %>Run Ruby, print nothing (loops, ifs)
